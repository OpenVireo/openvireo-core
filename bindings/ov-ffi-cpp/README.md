# ov-ffi-cpp

The C++17 binding of the openvireo-core facade, made with [cxx](https://cxx.rs). The desktop (Qt) links it as
`libovcore` and includes `<ovcore.h>`. Next to the facade it bridges the pieces below it that the desktop's account
code calls directly: the ov v1 crypto, the OPAQUE client steps (plus a test-only server half) and the sync merge on
serialized vaults (see [Below the facade](#below-the-facade) and [Desktop swap](#desktop-swap)).

## Getting it

Pick one:

- **Prebuilt package:** `cargo xtask cpp [--target <triple>]...` writes a CMake package to
  `target/ovcore-cpp/<target>/`. Without `--target` it builds `universal-apple-darwin` on macOS (arm64 + x86_64,
  joined with `lipo`) and the host triple elsewhere. The release targets are `universal-apple-darwin`,
  `x86_64-pc-windows-msvc`, `aarch64-pc-windows-msvc`, `x86_64-unknown-linux-gnu` and
  `aarch64-unknown-linux-gnu`. Each one needs `rustup target add <triple>` and a C++ compiler for that target.

  ```cmake
  find_package(OpenVireoCore 0.0 REQUIRED)        # -DOpenVireoCore_DIR=<pkg>/lib/cmake/OpenVireoCore
  target_link_libraries(app PRIVATE OpenVireoCore::ovcore)
  ```

  The imported target brings the include directory, C++17 and the system libraries rustc reports
  (`--print native-static-libs`). `smoke/` is the acceptance test for the package.
- **From source with Corrosion,** as the desktop does: see `example/CMakeLists.txt`. Corrosion runs cargo. When
  `OV_CXX_INCLUDE_DIR` is set, `build.rs` exports the headers there. Corrosion v0.6 builds one Rust target per
  configure, so a universal macOS app uses the prebuilt package (or one configure per arch, then `lipo`).
  **On aarch64, pass `CARGO_TARGET_<TRIPLE>_RUSTFLAGS=--cfg aes_armv8`** (the example does): Corrosion runs cargo
  outside this repo, so `.cargo/config.toml` isn't read, and without the cfg AES-KDF runs in software (~30x slower).

- **Test server:** the `test-server` cargo feature (off by default) builds in opaque-ke's server half, the
  seeded OPAQUE client steps and the in-process [test servers](#test-servers), for tests that stand in for the auth server. Without it those functions still
  exist (same header) but fail with `internal`; `ov::test_server_enabled()` says which build you have. Turn it on
  only for test builds:

  ```cmake
  # Corrosion (the desktop: only when WITH_TESTS)
  corrosion_import_crate(MANIFEST_PATH ... CRATES ov-ffi-cpp CRATE_TYPES staticlib FEATURES test-server)
  ```

  For the prebuilt package, `cargo xtask cpp --features test-server`; its `OpenVireoCoreConfig.cmake` then sets
  `OpenVireoCore_FEATURES` to `test-server`. A wrapper crate that depends on ov-ffi-cpp forwards it with
  `test-server = ["ov-ffi-cpp/test-server"]`. Never ship a release built with it.

Both paths build for macOS 11.0 and later unless `MACOSX_DEPLOYMENT_TARGET` / `CMAKE_OSX_DEPLOYMENT_TARGET`
says otherwise.

## Header layout

```text
include/ovcore.h                         include this
include/ov-ffi-cpp/include/ovcore.h      ov::Error, ov::call(), ov::wipe()
include/ov-ffi-cpp/include/host.h        the Host interfaces you implement
include/ov-ffi-cpp/src/lib.rs.h          generated by cxx: records, enums, handles, functions
include/rust/cxx.h                       cxx runtime (rust::String, rust::Vec, rust::Box, ...)
```

## Design

### Threading: blocking calls plus a CancelToken

Every facade call that is `async` in Rust (network, KDF, Host I/O) is a **blocking** C++ call. It runs the
core future to completion on the calling thread with `futures::executor::block_on`, and it takes an
`ov::CancelToken`. The other choice was callback-based completion. Blocking calls won for these reasons:

- **The core does no I/O of its own.** Every await ends in a Host call, and the C++ Host methods are synchronous.
  So there is nothing to drive in the background, and no Rust runtime or thread pool sits inside `libovcore`.
- **Qt already has the worker side.** The desktop calls the core from `QtConcurrent::run` / a `QThreadPool`
  task and gets the result back with a `QFutureWatcher` or a queued signal. A callback API would need the same
  thread hop plus lifetime rules for callbacks that outlive their caller.
- **Cancellation stays simple.** Keep `token->clone()` on the GUI thread and call `cancel()` on it. The core
  checks the token between steps. The edge also races the call against `CancelToken::cancelled()`, so a pending
  core future is dropped and the call returns `aborted` right away. A call made with a token that is already
  cancelled returns `aborted` without starting.
- **Host callbacks run on the caller's thread.** That thread is the worker that made the core call, never a
  hidden Rust thread. This keeps Qt's thread-affinity rules easy to follow. (A `QNetworkAccessManager` transport
  runs a local `QEventLoop`, or hands the request to a network thread and waits.)

Never call a blocking function on the GUI thread. A few facade calls are async but take no token (local
secure-store and cache reads such as `stored_session`, `park_session`, `keep_edits`); they block too, without a
`CancelToken`. The handles (`rust::Box<ov::Client>`, `ov::Account`, `ov::Vault`, `ov::ServiceAccount`,
`ov::SelfHosted`, ...) are `Send + Sync` in Rust, so several workers may share one handle (pass it by reference).

### Host

`include/host.h` declares one pure-virtual class per Host trait: `HttpTransport`, `ByteStream`, `SecureStore`,
`BlobCache`, `Clock` and `LogSink`. `SecureStore::delete` is named `remove` because `delete` is a C++ keyword.
Pass them to `ov::new_client()` as `std::unique_ptr`. Their rules:

- They must be thread-safe, because the core may call them concurrently.
- Transport failures go in `TransportFailure{kind, message}`, mapped to `TransportError`. Any other failure is
  thrown. A `what()` that starts with a wire code and `": "` (for example `"forbidden: keychain locked"`) keeps
  that code. Anything else becomes `internal`.

### Errors and panics

Every bridged function catches panics and returns `OvError{code: internal}`. A failure throws `rust::Error` with the text
`"<wire code>: <message>"`. The full `OvError` (code, message, status, retry-after, details JSON, server code)
is saved for the calling thread. Wrap calls in `ov::call([&]{ ... })` to get an `ov::Error` that carries all
of it:

```cpp
try {
    auto vaults = ov::call([&] { return account->vaults(*cancel); });
} catch (const ov::Error &e) {
    if (e.code() == "plan_limit") { /* e.info().details is JSON */ }
}
```

### Records

Records cross as flat shared structs. cxx shared structs can't hold `Option`, so:

- `Option<String>` is an empty string.
- Other options are a `has_x` flag plus a value.
- Enums are cxx shared enums. A value C++ made up (outside the declared ones) is rejected with
  `invalid_request`.
- Optional results that aren't strings come back as `Optional*` structs (`OptionalBytes`, `OptionalPlan`,
  `OptionalVaultInfo`, ...) with a `has` flag. Optional `Vec<String>` inputs (the group ids of an export) are an
  empty list for "every group"; `KdfOverrides` with no `has_*` set means the defaults.
- Rust enums with data are flattened to a `kind` plus fields: `ImportMode`, `Grantee`, `EntryExpiry`,
  `ExpiryChange`, `LocalImportMode`, `KdbxKdf`. `EntryInput::custom_icon` (`Option<Option<String>>`) is
  `custom_icon_change` (`Keep` / `Clear` / `Set`) plus `custom_icon`.
- contract-v1.6 added trailing fields to `EntrySummary`, `EntryRecord`, `AttachmentInfo` and `EntryInput`;
  aggregate initializers that leave them out still compile and change nothing (`Keep`, `has_* = false`).
- A record field named `protected` in Rust is `is_protected` (a C++ keyword); an `OvError` inside a record is an
  `ErrorInfo`; a list of secrets is `rust::Vec<ov::Bytes>`.

Secrets (`password`, `secret_key`, `auk`, field values, `.kdbx` bytes) cross as `rust::Vec<uint8_t>`. Inputs
move into the core, which wipes them. The caller wipes outputs with `ov::wipe()`.

## Below the facade

Free functions in namespace `ov`, synchronous and CPU-only (the OPAQUE steps run Argon2id, so keep them off the GUI
thread). They take `rust::Slice<const uint8_t>` inputs the caller keeps and wipes, and return secrets as
`rust::Vec<uint8_t>` for the caller to `ov::wipe()`. Text passed as bytes (AADs, passwords, `idU`/`idS`, the OPAQUE
context) must be UTF-8. Fixed nonces, ephemeral keys and seeds exist for the test vectors only: pass them empty to
get fresh random ones. Failures throw `rust::Error` (`"<wire code>: <message>"`), so `ov::call()` works as for
the facade.

| Area | Functions |
|---|---|
| Secret Key, NFKC (SPEC §2, §3) | `generate_secret_key`, `format_secret_key`, `parse_secret_key`, `nfkc_utf8` |
| Envelopes (SPEC §4, §6) | `wrap(key, plaintext, aad, nonce)`, `unwrap`, `seal(recipient_pk, plaintext, aad, ephemeral_sk, nonce)` (ov-crypto `seal_with`), `unseal`, `seal_derived_key` |
| Curves | `x25519_public_key`, `x25519_shared`, `ed25519_public_key`, `ed25519_sign`, `ed25519_verify` |
| Keysets (SPEC §5, §7) | `keyset_from_secrets` (returns `ov::PublicKeys` with the fingerprint), `verify_public_keys`, `fingerprint`, `vault_name_key` |
| Tokens (SPEC §9, §15) | `refresh_token_hash`, `build_service_account_token`, `parse_service_account_token` (`ov::ServiceAccountToken`), `service_account_secret_hash`, `service_account_secret_prefix` |
| OPAQUE client (SPEC §8) | `opaque_start_registration`, `opaque_finish_registration`, `opaque_start_login`, `opaque_finish_login` (`ov::OpaqueStart`, `ov::OpaqueLogin`) |
| OPAQUE, test-server only | `test_server_enabled`; seeded client steps `opaque_{start,finish}_{registration,login}_seeded` (a ChaCha20 seed, as in `vectors/opaque-transcripts.json`); server half `opaque_server_registration_response[_seeded]`, `opaque_server_store_record`, `opaque_server_credential_response[_seeded]`, `opaque_server_user_auth` (`ov::OpaqueServerStep`) |
| Sync merge | `merge_kdbx(local, local_key, remote, remote_key, base, base_key, now)` → `ov::KdbxMergeResult` |

`merge_kdbx` is ov-merge's three-way `merge_in_place` on two KDBX copies and their common base (empty `base`: none),
at `now` (Unix seconds). Each key is the copy's composite key as one or two raw 32-byte components (password and/or
key file, in KeePassXC's order). The intended use, as the desktop does: serialise the copies with a **throwaway
key** (32 random bytes as the password component), so the user's vault key never crosses; load the merged bytes back
with the same key. A copy comes back (written with its own key and KDF) only when the merge changed it
(`local_changed` / `remote_changed`); otherwise its bytes are empty. `changes` lists every change
(`ov::KdbxMergeChange`: `ov::ChangeType`, `ov::ChangeSubject`, the 16-byte RFC 4122 uuid or empty for the database,
title, group, details) and `conflicts` the entries both sides edited differently.

## Test servers

For the desktop's account tests (W3-ID2): with feature `test-server`, W2-E's in-process auth and sync servers
(`ov_testkit::servers`, the ones every core test runs against) are bridged, so the desktop's own Host (CoreHost)
can drive the real protocol without a network or the local stack. Without the feature the functions exist (same
header) and `ov::test_servers_start` fails with `internal`.

Design:

- `ov::test_servers_start(now_ms)` returns an `ov::TestServers` handle: both servers on one manual clock
  (`now_ms == 0` is the testkit default, 2026-11-15T00:00:00Z). `issuer()` is `https://auth.test`, `sync_url()`
  `https://sync.test/api/v1` (the self-hosted server URL is that without `/api/v1`).
- **Transport:** the test's `ov::HttpTransport::send` forwards to `servers->handle(req, failure)` (failures land in
  `failure`, exactly as a transport reports them), and `open_stream` to `servers->open_stream(req, failure)`, whose
  `ov::TestStream` is polled without blocking: `poll_chunk()` → `{Data, data}`, `{Pending}` or `{End}`. Hosts
  other than `auth.test` / `sync.test` fail as offline.
- **Clock:** the test's `ov::Clock` returns `servers->now_ms()`; `advance_ms()` / `set_now_ms()` move time (token
  expiry, the deletion grace period, refresh grace).
- **Store and cache** stay the desktop's own (keychain fake, `AccountOfflineCache`). `servers->client(config)` is a
  shortcut that builds a whole `ov::Client` on the servers' Rust Host (memory store and cache) instead.
- **Seeding and accidents:** `set_offline`, `fail_next(server, method, path_contains, status, times)` (`status
  0` = transport failure), `clear_faults`, `set_server_clock_skew_ms`, `requests()` (`"<status> <route>"`, never
  headers or bodies), `set_live_access`; blobs: `vault_blob`, `vault_revision`, `put_vault_blob` (another device),
  `rollback_vault` (`server_rolled_back`), `lose_vault` (`server_lost_database`), `add_device_token`,
  `close_streams`; accounts: `user_id`, `set_totp_code` / `totp_now` (MFA), `email_code`, `approve_reset`
  (recovery), `invitation_token`, `add_member`, `revoke_sessions` (revocation: the session ends),
  `access_events()` (JSON), `set_deletion_days` (deletion grace), `set_access_token_ttl_secs`,
  `set_recent_token_ms`. Users, vaults and orgs are made through the facade itself (`register_account`,
  `create_vault`, ...), so the fixtures are real protocol state.

`smoke/contract_v16.cpp` (`desktop_flow`) runs this end to end through a C++ Host; `tests/test_servers.rs` covers
the Rust side.

## Desktop swap

W3-ID's desktop-local `ovd` bridge (`src/account/ovcore/`, header `<ovdesktop.h>`) moved here. For W3-ID2:

1. Include `<ovcore.h>` instead of `<ovdesktop.h>`, and replace `ovd::` with `ov::`.
2. Build ov-ffi-cpp instead of `ov-desktop`. Either import it with Corrosion from a pinned openvireo-core checkout
   (`CRATES ov-ffi-cpp`, link `ov_ffi_cpp`, `FEATURES test-server` under `WITH_TESTS`), or keep
   `src/account/ovcore/` as a wrapper crate with no bridge of its own: `ov-ffi-cpp` as its only dependency (git
   rev, so `Cargo.lock` still pins the core), `src/lib.rs` = `pub use ov_ffi_cpp;`, and
   `[features] test-server = ["ov-ffi-cpp/test-server"]`. Either way `OV_CXX_INCLUDE_DIR` makes ov-ffi-cpp's build
   script export the headers, and the `--cfg aes_armv8` rustflags stay. Delete `ovd`'s `build.rs` and bridge.
3. The two calls below change shape; everything else is the same name, arguments and result fields.

| `ovd::` (W3-ID) | `ov::` (ov-ffi-cpp) |
|---|---|
| `nfkc_utf8`, `generate_secret_key`, `format_secret_key`, `parse_secret_key` | same |
| `wrap`, `unwrap`, `seal`, `unseal`, `seal_derived_key` | same |
| `x25519_public_key`, `x25519_shared`, `ed25519_public_key`, `ed25519_sign`, `ed25519_verify` | same |
| `keyset_from_secrets` → `ovd::PublicKeys{enc_pk, sign_pk, sig}` | `keyset_from_secrets` → `ov::PublicKeys{enc_pk, sign_pk, sig, fingerprint}` (the facade's record; one more field) |
| `verify_public_keys`, `fingerprint`, `vault_name_key`, `refresh_token_hash` | same |
| `build_service_account_token`, `parse_service_account_token` → `ovd::ServiceAccountToken` | same → `ov::ServiceAccountToken` (same fields) |
| `service_account_secret_hash`, `service_account_secret_prefix` | same |
| `opaque_start_registration`, `opaque_finish_registration`, `opaque_start_login`, `opaque_finish_login` (`ovd::OpaqueStart`, `ovd::OpaqueLogin`) | same (`ov::OpaqueStart`, `ov::OpaqueLogin`, same fields) |
| `opaque_start_login_seeded`, `opaque_finish_login_seeded` (feature `test-server`) | same (feature `test-server`); new: `opaque_start_registration_seeded`, `opaque_finish_registration_seeded` |
| `opaque_server_registration_response`, `opaque_server_store_record`, `opaque_server_credential_response`, `opaque_server_user_auth` (`ovd::OpaqueServerStep`) | same (`ov::OpaqueServerStep`); new: `opaque_server_registration_response_seeded`, `opaque_server_credential_response_seeded`, `test_server_enabled` |
| `merge_kdbx(local, local_key, remote, remote_key, base, base_key, now)` → `ovd::MergeResult` | same arguments → `ov::KdbxMergeResult`: `local`, `remote`, `local_changed`, `remote_changed` as before; `changes` are `ov::KdbxMergeChange` whose `change` is `ov::ChangeType` (was `uint8_t` 0 added … 4 metadata) and `subject` is `ov::ChangeSubject` (was 0 entry, 1 group, 2 database); `uuid` and `details` as before, plus `title` and `group`; new `conflicts` |
| errors: `rust::Error`, `what()` = `"<wire code>: <message>"` | the same, and `ov::call()` turns it into `ov::Error` with the whole OvError |

In `SyncEngine::mergeAccountVault`, `changeType(change.change)` switches on `ov::ChangeType`, and
`change.subject == 0` / `== 1` become `== ov::ChangeSubject::Entry` / `Group`.

## Coverage

**All bridged:** every public method and free function of `ov_core::api` (234 items since contract-v1.6, see
`docs/api-coverage.md` for how they map to the TS SDK and iOS) has a C++ function, with one deliberate exclusion.
`cargo xtask cpp --check-coverage` (also part of `cargo test -p ov-ffi-cpp`, so of `cargo xtask ci`) scans
`crates/ov-core/src/api/*.rs` and the bridge in `src/lib.rs` and fails, naming each one, when a facade item has no
bridged function.

How facade names become C++ names:

| Facade | C++ |
|---|---|
| a method `T::m` | `m` on the handle (`OvClient` is `ov::Client`) |
| an associated function `T::f` (no `self`) | the free function `t_f`: `ov::vault_open_local`, `ov::service_account_from_token`, `ov::self_hosted_connect` / `_pair` / `_restore`, `ov::plan_limit` / `plan_has` / `plan_has_billing`, `ov::platform_as_str` |
| `OvClient::new`, `CancelToken::new` | `ov::new_client`, `ov::new_cancel_token` |
| `Account::register` | `Account::register_account` (`register` is a C++ keyword) |
| a free function | the same name in namespace `ov` |

| Area | Bridged |
|---|---|
| Free | `version`, `take_last_error`, the crypto primitives, the functions [below the facade](#below-the-facade); `deletion_expired`, `default_share_fields`, `shareable_fields`, `item_share_payload`, `text_share_payload`, `parse_totp_uri`, `totp_code`, `entry_totp_uri`; record helpers `plan_limit`, `plan_has`, `plan_has_billing`, `platform_as_str` |
| `CancelToken` | `new_cancel_token`, `clone`, `cancel`, `is_cancelled`, `check` |
| `ov::Client` | everything: discovery, `connect`, `config`, local files on the Host clock (`open_local`, `create_local`), remembered accounts (`remembered_accounts`, `remember_account`, `set_remembered_deletion`, `mark_remembered_checked`, `forget_remembered`), `session_state`, `has_pending_edits`, signed-out share links (`share_info`, `open_share`) |
| `Account` | everything (contract-v1.6: `vault_kdbx_credentials`, `sync_vault_kdbx` with `ov::SyncOptions`, `access_token`): state and sessions (incl. `signed_out`, `verify_session`, parked sessions, `sign_out_on_unload`, `unlocked_keyset_secret` / `resume_unlocked`), register / login / TOTP / unlock, vaults and import, history, AutoFill edits, settings and two-step, devices, recovery, deletion, plans and In-App Purchase, vault sharing, orgs, audit log, service-account admin, share links |
| `LoginStep` / `TotpChallenge` | `needs_totp`, `challenge`, `take_unlocked`; `attempt`, `last_error` |

| `ServiceAccount` | everything (incl. `server_config`, `issuer`) |
| `SelfHosted` | everything (incl. `history`, `open_version`); `restore` returns `RestoredSelfHosted` (`is_paired()`, then `take()`) |
| `EventStream` | `next` (`kind == Closed` for the end), `reconnect`, `close` |
| Host | all six traits |

Deliberately not bridged:

- `CancelToken::cancelled`: it returns a Rust future. Every blocking call already races against it inside the
  bridge, and C++ code polls `is_cancelled()` or calls `check()`.

## Tests

- `cargo test -p ov-ffi-cpp`: the edge (panics, error fields, cancellation), conversions (records round-trip,
  made-up enum values rejected), primitives, the record helpers, `tests/coverage.rs` (every facade item is
  bridged; `cargo xtask cpp --check-coverage` prints its report), the crypto functions against
  `vectors/test-vectors.json`, the OPAQUE client steps, and `tests/merge_kdbx.rs` (all 14 merge fixtures through
  `merge_kdbx` as KDBX bytes, plus a check that `smoke/fixtures/*.kdbx` still are those fixtures).
  `cargo test -p ov-ffi-cpp --features test-server` adds the OPAQUE transcript replays (libopaque and opaque-ke).
- `smoke/`: builds against the `cargo xtask cpp` package and runs with an offline Host (no server). It calls
  `version()` and `sha256("abc")`, checks an OvError through `ov::call` and a cancelled call coming back as
  `aborted`, then calls at least one method of every bridged area: network calls (register, recovery, settings,
  devices, deletion, sharing, orgs, plans, service accounts, share links, history, self-hosted) must come back as
  an `ov::Error` with a real code (`network_error`, `signed_out`, `invalid_token`, ...), never `internal` or a
  crash; local work is checked for its values (a local vault: add, edit with history, version diff, plain export,
  delete to the Recycle Bin, save and reopen; RFC 6238 TOTP; share payloads; the record helpers;
  `Client::config`). A compiled-but-never-called function type-checks more of the API against the header.
  `below_facade.cpp` checks every function below the facade against `vectors/test-vectors.json`,
  `vectors/opaque-transcripts.json` (with a `--features test-server` package: the replay of a login to an account
  libopaque registered, and the whole opaque-ke run through the server half) and two merge fixtures
  (`smoke/fixtures/*.kdbx`, written by `cargo test -p ov-ffi-cpp --test merge_kdbx -- --ignored
  write_smoke_fixtures`), whose merged copies it opens with `vault_open_local` and compares with the fixture's
  expected result. `contract_v16.cpp` checks the contract-v1.6 additions on local vaults (values, errors,
  the Host clock) and `SelfHosted::history` / `open_version` over a canned transport.
- `example/`: the Corrosion build of the same core.
