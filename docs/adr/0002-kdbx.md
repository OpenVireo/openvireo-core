# ADR 0002: `ov-kdbx` is our own crate, not keepass-rs

- Status: **accepted** 2026-11-15 (signed off by the user; lead merged W1-K1). `keepass` removed and `salsa20 =0.10.2` allowed in `contract-v1.3`. K3 moves `spikes/kdbx/files/` + `gen-kdbxweb.mjs` into `corpus/kdbx/` and deletes `spikes/kdbx/`.
- Date: 2026-11-15
- Plan: `openvireo-dev-guide/plans/rust-core.md` (Phase 0 spike, Phase 5); tasks
  `plans/rust-core-tasks.md`, cards W1-K1, W1-K2 and W1-K3
- Evidence: `spikes/kdbx/` at commit `4ccbac6` (`check.sh`, `gen-kdbxweb.mjs`, `src/`; deleted by W1-K3, the test files now live in `corpus/kdbx/`). It's a standalone package with its
  own `[workspace]` and lockfile, outside the root workspace, and gets deleted after sign-off.

## Decision

**Own crate.** K2 writes the KDBX reader and writer in `ov-kdbx`, straight onto the frozen model
(`model.rs`), using `quick-xml`'s pull reader and writer (not serde). The iOS Swift KDBX code
(`OpenVireoCore/KDBX`, 2,257 lines) is the map. `keepass` comes off the allow-list.

keepass-rs 0.17.0 opens every test file and writes files that KeePassXC opens, but it fails the gate
on what matters most here: **unknown elements**. An unknown child of `<Group>` (or `<Root>`, in
0.8.16) makes the **whole file fail to open**. Unknown children of `<Meta>`, `<Entry>` and
`<AutoType>` are **silently dropped** on save. Its model also loses order (string fields, custom data
and deleted objects are `HashMap`s), and it writes only KDBX 4.1. Fixing that means replacing its
serde XML layer and its model, which is most of the crate. At that point we'd have our own crate,
plus a second RustCrypto generation and eleven crates that aren't on the allow-list.

## What was tested

keepass-rs 0.17.0 (`features = ["save_kdbx4"]`, MIT). For each file: open it with keepass-rs and save
it as KDBX 4.x with the same key, then compare the original and the rewrite. The comparison uses
the desktop CLI (`openvireo/build/src/cli/openvireo-cli export`, KeePassXC 2.8.0-snapshot renamed;
there's no `keepassxc-cli` on PATH) and the raw decrypted XML from keepass-rs `get_xml`.

| File | Writer | Format | Key |
|---|---|---|---|
| `vectors/vault-fixture.kdbx` | contract fixture (kdbxweb) | KDBX 4.0, Argon2id | raw 32-byte vault key file only |
| `vectors/kdbx/desktop-kdbx31.kdbx` | desktop CLI | KDBX 3.1, AES-KDF, AES-256 | password |
| `vectors/kdbx/desktop-kdbx4-argon2d.kdbx` | iOS, then desktop CLI | KDBX 4.0, Argon2d | password |
| `files/kdbxweb-vault.kdbx` | SDK `createVaultKdbx` (kdbxweb 2.1.1) | KDBX 4.0, Argon2id 1 MiB/2/1 | raw vault key |
| `files/kdbxweb-unknown.kdbx` | kdbxweb, plus `Zz*` elements in KeePassFile, Meta, Root, Group, Entry, AutoType | KDBX 4.0 | password |
| `files/kdbxweb-unknown-leaf.kdbx` | the same, with unknown elements only in Meta, Entry, AutoType | KDBX 4.0 | password |
| `files/ios-interop.kdbx` | iOS app `DesktopInteropTests.writeInteropSource()` (simulator) | KDBX 4.0, Argon2d | password |
| `files/ios-passkey.kdbx` | iOS app `PasskeyTests.writesInteropFile()` (simulator) | KDBX 4.0, AES-KDF | password |

The kdbxweb files hold custom and protected fields, history, an attachment, tags, colours, an override
URL, an auto-type association, custom data on Meta, a group and an entry, a recycle bin and a
`DeletedObjects` tombstone. The iOS files hold a protected custom field, an attachment and passkey
fields.

## Evidence for the four checks

### 1. Lossless read: fails

Every file opens (KDBX 3.1 and 4.0, AES-KDF, Argon2d and Argon2id, AES and ChaCha20, the raw
32-byte key file). Its own output reopens equal on its own model. But reading into keepass-rs
loses information that `model.rs` must keep:

| Model requirement (§2.5) | keepass-rs 0.17.0 | Gap for an adapter |
|---|---|---|
| `unknown` passthrough on Database, Meta, Group, Entry, AutoType | none: typed serde structs, no catch-all. An unknown `<Group>` child is a hard error (`unknown variant 'ZzUnknownGroup', expected 'Group' or 'Entry'`); other unknowns are dropped | **not fixable from outside** |
| String fields in file order | `HashMap<String, Value<String>>`. The rewrite reordered `Title, UserName, Password, URL, Notes, Zeta custom, Alpha custom, PIN` to `Zeta custom, Notes, URL, UserName, Password, Title, PIN, Alpha custom` | not fixable from outside |
| Custom data in file order, with `LastModificationTime` | `HashMap<String, CustomDataItem>` (times are kept) | order lost |
| `DeletedObjects` in file order | `HashMap<Uuid, Option<NaiveDateTime>>` | order lost; content kept |
| `QualityCheck: Option<bool>` | `bool`, always written (`<QualityCheck>True</QualityCheck>` added to every entry and history item) | absent and `True` can't be told apart |
| Header `unknown_fields` | unknown outer-header field is an error (`InvalidEntry`) | not fixable from outside |
| `LocationChanged`, history, memory protection, custom icons (with 4.1 name/time), binaries + protected flag, `PreviousParentGroup` | kept (some behind `pub(crate)` with getters) | ok |
| KDBX 3.1 read (ISO times, `Meta/Binaries`, Salsa20 inner stream) | reads it; times decode to the same seconds | ok |
| Raw 32-byte key file component | `with_keyfile`: XML, then 32 raw bytes, then 64 hex, then SHA-256 (as KeePassXC) | ok |

### 2. Write, then reopen in KeePassXC: passes, with caveats

`openvireo-cli export` opens every rewrite with the same entry count. The KeePassXC-visible diffs
are format changes (3.1 ISO times become 4.x binary times with equal values, binaries move to the
inner header) plus the losses above: custom data reordered, `MasterKeyChanged` empty becomes
"now", `SettingsChanged` and `QualityCheck` added. The two iOS files showed a 0-line diff.

Caveat: `dump_kdbx4` accepts only `KDB4(1)`, so keepass-rs can't write KDBX 4.0 (or 3.1). Writing a
4.0 vault means upgrading it to 4.1.

### 3. Unknown-element passthrough: fails

- `kdbxweb-unknown.kdbx`: KeePassXC opens it (it logs `skipCurrentElement` for all six `Zz*`
  elements). keepass-rs **fails to open it**.
- `kdbxweb-unknown-leaf.kdbx`: keepass-rs opens it, and the rewrite has **0 of 3** unknown
  elements.
- keepass 0.8.16 (the last version on our digest-0.10 crypto generation; xml-rs parser) was also
  tried: `open failed: Bad XML event: expected valid Root child, got Start("ZzUnknownRoot", {})`. It
  also dropped the leaf unknowns (`Zz elements after rewrite: 0`).

### 4. Builds for wasm32-unknown-unknown and aarch64-apple-ios: passes, but at a cost

`spikes/kdbx/src/lib.rs` exports one function that links open and save. Both targets build. iOS
gives an arm64 Mach-O dylib. wasm sizes use the workspace release profile (`opt-level="z"`, LTO,
1 CGU, strip):

| | raw | `wasm-opt -Oz` | gzip -9 of opt |
|---|---|---|---|
| baseline (same export, no keepass) | 16,126 | 13,753 | 6,134 |
| with keepass-rs | 1,214,668 | 1,038,879 | 341,232 |

That's **about 1.0 MB raw / 335 KB gzipped** for KDBX alone. By crate (code bytes, unstripped
build): quick_xml 234 KB (serde de/ser monomorphisation), keepass 128 KB, hashbrown 43 KB,
chrono 37 KB, js_sys 30 KB, miniz_oxide 28 KB, sha2 20 KB, aes 18 KB, blake2b_simd 18 KB.

### Licences and dependencies

With the root `deny.toml`, `cargo deny check licenses bans sources advisories` on the spike gives
`advisories ok, bans ok, licenses ok, sources ok`. The licences are fine. The dependency set is not:

- **Second RustCrypto generation.** keepass 0.17 uses sha2 0.11, hmac 0.13, digest 0.11, cipher 0.5,
  aes 0.9, cbc 0.2, chacha20 0.10, getrandom 0.4 and base64 0.23. The workspace is pinned to the
  generation opaque-ke 4.0.1 uses (sha2 0.10.9, hmac 0.12.1, chacha20 0.9.1, getrandom 0.2.17,
  base64 0.22.1). Every client would ship both.
- **Not on the §2.6 allow-list:** chrono (+ iana-time-zone, core-foundation-sys), rust-argon2
  (+ blake2b_simd, crossbeam-utils, constant_time_eq), salsa20, twofish, block-modes, hybrid-array,
  indexmap, byteorder and hex-literal.

## Consequences

### What K2 builds (`crates/ov-kdbx`, card W1-K2, size L)

Estimate: about 3,000 lines plus tests, in line with rust-core.md's estimate for an own crate. Only
allow-listed crates are used, except as noted.

1. `header`: outer header read/write for 3.1 and 4.x; VariantDictionary (all seven types, kept in
   order); unknown header fields go to `Header::unknown_fields`; 4.x inner header (stream id/key,
   binaries with protected flag). About 400 lines.
2. `crypto`: composite key (password SHA-256, key file: XML v1/v2, raw 32 bytes, 64 hex, else
   SHA-256), AES-KDF (`aes`), Argon2d/id (`argon2`), AES-256-CBC (`aes` + `cbc`), ChaCha20 payload
   and inner stream (`chacha20`), HMAC-SHA256 block stream (4.x), SHA-256 hashed block stream and
   `HeaderHash` (3.1), gzip (`flate2`). About 500 lines.
3. `xml`: a pull reader and writer on `quick-xml` (`Reader`/`Writer`, no serde) that fills
   `model.rs`. Every element KeePassXC's `KdbxXmlReader` knows maps to a field; anything else becomes
   an `XmlElement` in the right `unknown` list and is written back in place. Protected values are
   inner-stream decrypted and re-encrypted in document order, including protected unknown elements.
   3.1 ISO 8601 times are parsed by hand (no chrono). About 1,300 lines.
4. `vault` helpers from `vault/kdbx.ts` (`vault_credentials`, `apply_vault_kdf`, `create_vault_kdbx`,
   `rekey_to_vault_key`, `copy_kdbx`, `drop_server_remotes`, `open_with_key_versions`,
   `sync_generation`), plus entry ops from `vault/entries.ts`. About 600 lines.
5. Writer emits KDBX 4.0 or 4.1 to match `Header::version`, so a 4.0 vault stays 4.0, and 3.1 is
   upgraded to 4.x. It doesn't add elements that weren't read (`QualityCheck` stays `None`).

**Salsa20.** KDBX 3.1 files use the Salsa20 inner stream (the desktop 3.1 fixture does). `salsa20`
isn't on the allow-list. K2 needs either an OWNER-REQUEST for `salsa20 =0.10.x` (the
cipher-0.4 generation, which matches `chacha20 =0.9.1`), or a small Salsa20 core written in
`ov-kdbx` (about 80 lines, tested against the eSTREAM vectors). This ADR recommends the crate. Twofish
is recognised (`Cipher::Twofish`) and returns `kdbx_error` "unsupported".

### What K3 gets from the spike

- The kdbxweb generator (`spikes/kdbx/gen-kdbxweb.mjs`, including the DOM-injection trick for
  unknown elements: kdbxweb rebuilds its XML on save, so unknowns are injected after `buildXml`).
  Move it to `corpus/kdbx/`.
- The iOS recipe: `TEST_RUNNER_OV_INTEROP_OUT=<path> xcodebuild test-without-building -project
  OpenVireo.xcodeproj -scheme OpenVireo -destination 'platform=iOS Simulator,…'
  '-only-testing:OpenVireoCoreTests/DesktopInteropTests/writeInteropSource()'`. Use the `OpenVireo`
  scheme (the `OpenVireoCore` scheme has no test action). Set the variable in the environment, not
  as a build-setting argument, and add `()` to Swift Testing identifiers.
- The KeePassXC CLI is `openvireo/build/src/cli/openvireo-cli`. The 2.8.0-snapshot is renamed, so
  there's no `keepassxc-cli` binary; `build-stale-keepassxc-path/` still has an old one.
- The acceptance bar this spike used: open, save, reopen, then compare the raw XML (order and
  unknown elements included) and the `openvireo-cli export`.

### Allow-list

Remove `keepass` from `[workspace.dependencies]` and §2.6. That's a lead/W0-A change, not made here.
